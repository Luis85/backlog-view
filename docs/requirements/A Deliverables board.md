# A Deliverables board

A second board, reserved for `Deliverable` items alone: its own toolbar toggle, and its
own workflow property and states, independent of the requirements board's. A Deliverable
still shows up everywhere else exactly like any other item — the tree, the roadmap, and
the general board too, in the leading no-state column if it carries no requirements
state and under its own state's column if it does, exactly like any other candidate
there.

**Outcome** — Concepts, designs and other deliverables get a kanban process of their
own, without the requirements board's workflow having to describe two different kinds of
work through one column list.

## Use cases

- [[A board scoped to Deliverables]] — the toggle, the columns, and the cards moving
  through a workflow of their own.
