# The roster comes from the notes

The resources axis draws one row per `Resource` note **the base returned**, and the
comma-separated `resourceNames` view option that declares a roster today is removed.

A resource stops being three things that had to agree — a typed option, an observed name, an
absence's subject — and becomes one note the results either carry or do not. That is the same
population rule every other row in this plugin already lives under, which is why it needs no
new read path and why the context-row rule keeps working unchanged: a `Resource` the base
excluded is not a row, and therefore never a drop target.

**Outcome** — The roster is the resource notes in the base, so adding a person to the roadmap
is making a note rather than editing a view setting.
