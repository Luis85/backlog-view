# Suggested property names, mapped by the user

The plugin publishes one suggested name per semantic concept — parent, order, status,
owner, estimate, objective, evidence, release, horizon, the planned dates, the dependency
edge — and every view offers its own suggestion from that list. The user maps each concept
to whatever their vault already calls it.

A suggestion is not a requirement, and a name the plugin suggests is never assumed: a key
nobody bound is read as absent, exactly as it is today.

**Outcome** — Two vaults with different property vocabularies both work, and neither has to
rename anything to adopt a view.
